Q1

Briefly describe a key Azure data platform you've built. What was the architecture, your direct role, and a critical technical trade-off you made?

End-to-End Enterprise Architecture:

Architected a scalable Medallion data platform utilizing Azure Data Lake Storage Gen2 (ADLS) for raw storage, Azure Data Factory & Apache Airflow for ingestion pipelines, Azure Databricks (PySpark / Delta Lake) coupled with dbt for Bronze → Silver → Gold transformations, and Azure Synapse / Power BI for analytical consumption.

My Direct Role

Lead Data Platform Architect and Engineer. Authored Terraform Infrastructure-as-Code modules, built ingestion frameworks, structured dbt transformation layers, and tuned Databricks clusters.

Critical Technical Trade-Off

Chose Databricks Delta Lake over native Azure Synapse SQL pools for heavy ETL/ELT. While this incurred slight cluster spin-up latency, it reduced compute costs dramatically for semi-structured data, offered superior PySpark parallelization, and guaranteed ACID consistency.

Q2

How do you structure your dbt projects and data models? Please share a real-world example of a transformation challenge you solved using dbt.

Multi-Layer Medallion Project Structure:

  • staging/ — Clean 1:1 source mappings, explicit schema casting, and normalized naming conventions.
  • intermediate/ — Complex business logic, stateful aggregations, and multi-source joins.
  • marts/ — Star-schema dimensional models (dim_ and fct_) optimized for high-performance BI queries.

💡 Real-World Transformation Challenge: Late-Arriving & Duplicate Event Logs

Problem: High-volume event stream data arrived out-of-order with duplicate entries, resulting in massive warehouse scan costs when executing full refreshes.

Solution: Engineered incremental dbt models using dynamic unique_key definitions combined with windowing functions:
ROW_NUMBER() OVER (PARTITION BY id ORDER BY updated_at DESC) alongside dbt snapshots. Result: Cut warehouse compute costs by over 40% while maintaining absolute pipeline idempotency.

Q3

Describe a recent project using Databricks. What was the workload type and how did you approach performance or cost optimization?

Workload: Large-scale PySpark ETL batch and near-real-time streaming pipelines transforming multi-terabyte log and financial event datasets into Delta Lake tables.

1. File Layout & Data Skipping

Implemented automated OPTIMIZE and ZORDER BY routines on high-cardinality join/filter keys. Eliminated the small-file bottleneck and enabled rapid predicate pushdown.

2. Cluster Cost Control

Configured aggressive auto-scaling with 15-minute idle auto-termination. Leveraged Azure Spot instances for worker nodes on fault-tolerant batch workloads to save cloud spend.

3. Memory & Join Tuning

Utilized PySpark broadcast joins for smaller dimensional lookups, completely avoiding costly cross-node network shuffles and accelerating pipeline throughput.
