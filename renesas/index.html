Interview Talking Points

How I Think About Renesas’ AI Problems

Anticipated deep-dive questions based on the JD — with answers grounded in systems I have already built.

Q1

How would you take an internal agentic portal and make it reusable across business groups?

Productize the agent runtime, not just the UI — this is an AI platform problem.

Separate (1) shared agent orchestration + tool registry, (2) domain skill packs (software, AI, embedded workflows), and (3) tenant-specific knowledge bases and policy profiles. Each business group gets its own retrieval corpus, tool ACL, and guardrail config — while sharing the same core runtime, eval harness, observability, and deployment pipeline. That is how you grow adoption without multiplying one-off agents.

What I’ve done

Reusable Kubeflow / ML platform components and multi-agent subsystems where specialist agents share orchestration but have scoped tool access.

Adoption lever

Ship Gradio/Streamlit eval surfaces early so each group can measure answer quality and trust before wider rollout.

Q2

How do you design secure on-prem / air-gapped agentic systems?

Security is a runtime property of the agent, not a network checkbox.

1. Isolation

Local open-source LLMs (vLLM), no outbound model calls, ZTNA or air-gap networking, secrets never in prompts or logs.

2. Tool ACLs

Every tool call is authorization-checked; high-risk actions require human approval; least privilege by default.

3. Audit & Guardrails

Fail-closed validation gates, content/policy filters, immutable hash-chained action logs for forensics and compliance.

Q3

How would you build an engineering knowledge assistant for code, debugging, and docs?

Hybrid RAG + tools beats pure chat.

Index repos, design docs, tickets, and runbooks with high-quality chunking and embeddings. Retrieve with hybrid search, then let agents call tools (read file, search code, run tests, open CI logs) under ACL. Always cite sources. Measure with an eval set of real engineer questions, not generic LLM benchmarks.

Relevant build

Production RAG with LangChain/LlamaIndex + Qdrant memory/RAG agents with Pydantic AI — pattern directly transferable to Renesas engineering workflows.

Q4

How do you choose and operate open-source LLMs for local serving?

Model choice follows task, latency budget, and VRAM — then harden the serving stack.

Serving

vLLM for high-throughput chat/agents; Triton when mixing modalities or needing ensemble routing. Size VRAM for context + concurrency.

Adaptation

Prefer LoRA/PEFT/SFT over full fine-tunes for domain specialization; keep base models swappable as open-source releases improve.

Ops

Prometheus/Grafana on latency, queue depth, GPU util; regression evals on agent success rate before promoting models.

Q5

How do you improve accuracy, reliability, and user adoption over time?

Treat the assistant as a product with telemetry and a feedback loop.

  • Golden-set evals for retrieval quality and agent task success
  • Thumbs-down / correction capture into curated fine-tune or prompt datasets
  • Guardrail false-positive/negative monitoring so security does not kill usability
  • Role-based onboarding: start with high-ROI workflows (docs Q&A, log triage) before write-actions
